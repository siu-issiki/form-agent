# 承認前の登録値派生

> 個別実装時点の記録です。統合時点の状態は[信頼性改善の検証記録](reliability-improvements-2026-09.md)を参照してください。

`mapRegistrationValues` が既存登録値から決定的に導けるキーを追加する。CSV CLI の job/payload 作成・承認 fingerprint 計算より前に行い、Worker の入力処理や既存ジョブの値は変更しない。

| 出力キー | 生成条件 | 明示値がある場合 |
|---|---|---|
| phoneDigits | phone の ASCII 数字・単独ハイフン/空白区切りを除去した先頭0の10/11桁 | 2件目以降の「電話番号」と「電話番号（数字のみ）」はすべて同じ番号であることを確認。電話3分割とも比較し、不完全な分割の先頭/末尾も照合。不正・不一致なら拒否 |
| fullNameHiragana | 姓・名のひらがな（ぁ～ゖ、ー）を空白なしで結合 | 既存フル値は半角/全角スペースの有無だけを同一視し、元表記を残す。派生可能なのに別の読みなら拒否 |
| emailLocalPart / emailDomain | 通常のASCII非引用メールアドレスを単一@で分割 | 「メールアドレス（@より前）」「メールアドレス（@より後）」があれば大小文字を含め一致確認。local partのタグ・大文字を維持 |
| postalCodeDigits | 郵便番号の7桁/3-4表記。または全文値がない場合の3桁＋4桁 | 「郵便番号（数字のみ）」の7桁値と比較し、不一致を拒否。全文と分割値の不一致も、片側だけでも3/4桁の位置を比較して拒否 |

元のphone/email/postalCodeと既存の姓名partsは保持する。電話の中間partがあるのに全境界が揃わない場合はphoneDigitsを生成しない（明示digits候補があれば比較不能として拒否）。分割の欠落分を創作しない。元表記が不明（国番号・内線・括弧・全角電話、quoted emailなど）の場合は推測変換せず新しい派生キーを省略する。電話の明示digits候補があるのに元電話と比較できない場合は拒否する。ひらがながない場合の漢字・カタカナからの読み創作、会社読み、ゼロ埋め、短文作成はしない。既存canonical/aliasの優先は維持するが、派生に直接対応する明示候補は黙って上書きしない。

従来の任意文字列をphoneDigitsにそのままコピーする挙動は廃止した。元phone="phone"一件は保持してphoneDigitsを省略し、2件目="phone-digits"は拒否するテストを残した。既存テストの電話ダミーは有効な国内番号へ変更したが、この非互換を隠さない。入力値をログや例外へ含めず、固定キー名のみで失敗を通知する。

新しい値は承認対象になるため、次campaignの別ID・別状態ディレクトリで準備と承認を作り直す必要がある。既存campaignの再prepare、manifest/journal/payload/D1変更、未確認ジョブの再送は行わない。一般senderの独立worktreeには統合担当が同じcommitを適用する必要がある。Worker deployは不要。

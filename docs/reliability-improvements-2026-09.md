# 送信処理の信頼性改善

この変更は管理下シナリオで検証し、2026年9月5日に本番へ反映した送信処理をmainへ統合するものです。キャンペーンの承認内容・既存ジョブの結果を変更したり、再送を開始したりする変更ではありません。

## 主な変更

- 送信内容の承認ダイジェストを照合し、独立dry-runを省いても送信直前の証跡・審査・状態再確認を維持する。
- CSVに明示されたHTTP/HTTPSとフラグメントを保持し、登録前に電話・郵便番号・氏名読み・分割メールを矛盾なく派生する。
- 遅延表示、可視ラベルを持つ選択肢、ARIAリスト、inputボタンの操作とfixed要素の証跡処理を改善する。
- 受付表示・ページの明示エラーを検出し、静的案内・引用・既存文・別フォーム・不可視表示を誤って成功にしない。
- CF7の同一フォームに新規受付と成功状態が出た場合を限定検出する。Chromeの入力欄内部DOMはサイトのShadow DOMと区別し、サイト側Shadow DOMや別フレームの安全境界は維持する。
- ローカル確認操作と実送信を区別する案内を具体化し、通信拒否・継続失敗に機密を含まない診断を加える。

## 検証

- 本番と同じソースで単体889件、Worker248件、型・lintを確認。
- 確認操作の旧版6件は5成功・1未確認。修正後6件は全成功し、click→observe→submit、送信・審査・受信各1回をD1で確認。
- 初回統合後の管理下14件は13件期待一致、CF7の正常受付だけ未確認が残った。ブラウザ内部DOMの差を修正後、正常受付・別フォーム・非表示・対応不明の4ケースはすべて期待どおり。
- この追加改善の管理下26ジョブについてD1/API/受信結果と66証跡のSHAを照合。通常キャンペーンの既存703件の状態・理由・試行回数は不変。

## 残る制約

モデルの確認操作選択を機械的に保証した変更ではありません。CF7についても検証したフォーム構造の範囲に限ります。入力validityの詳細と証跡取得失敗の分類強化は追加候補です。未確認の送信を自動再試行する許可は追加していません。
